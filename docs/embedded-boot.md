# Embedded Boot

## Objective

Define a bootable embedded image separate from desktop/server images for the
primary target (x86-64 QEMU q35 embedded-configured).

## Boot requirements

| Item | Value |
|------|-------|
| Firmware / bootloader | QEMU firmware (OVMF UEFI) or direct kernel boot via multiboot/limine |
| Entry point | Kernel entry as defined by `x86_64-unknown-none` bare-metal target |
| CPU state at entry | As defined by the existing bare-metal boot path |
| Memory map | Documented per image; kernel reserved, heap, device regions |
| Device-tree location | Passed via boot argument or embedded in image (TBD per layout) |
| Kernel location | Defined by image format below |
| Initial stack | Existing bare-metal boot stack |
| Boot arguments | Console device, root device, profile, log level, read-only flag |
| Console configuration | Serial (ISA debug-exit / debugcon) |
| Image format | Raw disk image with boot metadata + kernel + root filesystem |
| Alignment requirements | Page-aligned (4 KiB) |
| Endianness | Little-endian (x86-64) |
| Compression | None for initial profile |
| Failure behavior | Serial diagnostic, stable failure code, watchdog-safe, no silent boot loop |

## Image components

An embedded image may contain:

```text
Boot metadata
Kernel
Hardware description (device tree or ACPI tables)
Initial filesystem (read-only system + writable state)
Application payload
Recovery metadata
Integrity metadata (signatures, checksums)
```

The initial embedded image is: **kernel plus read-only root filesystem plus
writable state partition**, generated reproducibly.

## Boot failure behavior

A failed boot must produce:

- Serial diagnostic if available
- Stable failure code
- Watchdog-safe behavior (do not feed watchdog during failed boot)
- Recovery or alternate-slot behavior
- No silent boot loop

## Image generation

The embedded image is generated by a reproducible build step (documented in
`docs/embedded-build.md` or equivalent) that:

- Takes the built kernel binary
- Packs the read-only root filesystem
- Creates the writable state partition
- Embeds hardware description
- Attaches integrity metadata
- Emits a single bootable image file

## Exit criteria

- [ ] Embedded image layout documented
- [ ] Image can be generated reproducibly
- [ ] Image boots on primary target
- [ ] Hardware description reaches the kernel
- [ ] Early console works
- [ ] Boot failure behavior is defined
- [ ] Existing desktop/server images remain unaffected
